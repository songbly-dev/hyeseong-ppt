# 소프트 덱 (airbnb)

> **흰 캔버스 · 14px 둥근 카드 · Rausch 핑크 한 점**

세 가지가 인상의 전부다. 원본 규격은 같은 폴더의 `design-spec.md`(getdesign `airbnb` DESIGN.md)에 있고,
그 문서 맨 위 "덱 번역표"가 원본 토큰을 이 덱의 클래스로 옮긴 기준이다.

minimal 과 **정반대의 모양 언어**를 쓴다. minimal 은 각지고 종이색이고 형광펜이다.
이 스타일은 둥글고 흰색이고 한 가지 핑크다. 두 스타일의 규칙을 섞지 않는다.

---

## 1. 절대 어기지 않는 것

```css
--paper:#ffffff;   /* ① 배경은 순백. 아이보리·회색 바탕 금지 */
--ink:#222222;     /* ② 검정이 아니라 #222. 순흑 #000 금지 */
--rausch:#ff385c;  /* ③ 브랜드색은 이 하나뿐 */
```

**③ Rausch 면(fill)은 한 장에 하나다.** 이쪽이 진짜 규칙이다.

| Rausch 면으로 치는 것 | 한 장에 |
|---|---|
| `.flow strong` (흐름의 결론 칸) | 이 중 **하나만** |
| `.band.rausch` | |
| `.prompt .skill` (프롬프트 라벨 알약) | |
| `.ui-btn` (예시 UI 버튼) | |
| 표지 `.orb` (검색 오브) | |

- 제목 `.accent`(Rausch **글자**)와 밴드 안 숫자 `.band b` 는 면이 아니라 글자라 세지 않는다.
- 두 개가 필요해 보이면 하나를 잉크 `#222` 로 바꾼다. 원본도 페이지의 90% 가 흰색+잉크이고 Rausch 는 한두 순간이다.
- 서브 브랜드색(Luxe `#460479`, Plus `#92174d`)은 쓰지 않는다.

**④ 본문 제목은 그 장의 내용을 그대로 쓴다. 후킹은 표지에서 이미 했다.**

```html
<h1>MCP 서버의 <span class="accent">세 가지 구성요소</span></h1>
<h2>연결 비용 <span class="accent">N×M vs N+M</span></h2>
```

- 한 줄, 명사구가 기본이다. 반문·반전·감탄 금지. 주장은 리드 한 문장과 결론 밴드가 한다.
- `.accent` 는 제목의 **핵심 명사**를 Rausch 글자색으로 칠한다. **한 장에 한 번만.**
- **`.accent` 는 제목 크기(32px 이상)에서만 쓴다.** 흰 바탕 위 Rausch 는 대비 3.5:1 이라 본문 크기에선 안 읽힌다.
  카드 안에서 강조가 필요하면 잉크 굵게(`<b>` / `font-weight:700`)로 한다.
- 표지 `h1` 에만 후킹 제목을 건다.

**⑤ 모든 면이 둥글다. 각진 것은 없다.**

| 대상 | radius |
|---|---|
| 버튼·예시 UI·편집 버튼 | `--r-sm` 8px |
| 카드·밴드·프롬프트·스크린샷 | `--r-md` 14px |
| 숫자 히어로·큰 스크린샷 | `--r-lg` 20px |
| 흐름·검색바·배지·장수 표시 | `--r-full` 알약 |
| 단계 번호·내비 버튼·오브 | 원 |

**⑥ 그림자는 한 단뿐이다 — `var(--lift)`.** 두 겹, 오프셋, 색 그림자 금지.
그림자는 **떠 있는 것**(흐름 알약, 표지 검색바, 숙소 카드 `.card.top`, 숫자 히어로, 배지, 장수 알약)에만 준다.
평범한 카드는 그림자 없이 `1px var(--line)` 헤어라인으로 나눈다.

**⑦ 굵기는 700 이 상한이다.** 800·850·900 금지(브랜드 워드마크 `.brand` 하나만 예외).
무게는 굵기가 아니라 여백과 면이 만든다. 제목 자간은 `-.03em`.

**⑧ 태그 나열 금지.** `.badge`(흰 알약)는 **카드 하나에 하나**, "고르는 쪽"·"추천"·"NEW" 같은 표시에만 쓴다.
주제어를 알약으로 줄 세우지 않는다.

## 2. 레이아웃

| 그 장이 하려는 것 | `<section class="…">` |
|---|---|
| 글과 그림이 짝을 이룬다 (정의+흐름, 비교, 절차) | `slide two dense` |
| 도해가 넓게 펼쳐져야 한다 (3열 카드, 벤, 숫자 히어로, 스크린샷) | `slide one` |
| 표지 | `slide title` |

한 장의 형태:

```
h1 / h2   — 핵심 명사에 .accent (한 장에 한 번)
p.body    — 1문장. 제목을 풀어 주는 한 줄
────────
도해 하나
결론 밴드 한 줄
```

**표지의 검색바 `.search`** — Airbnb 검색바를 빌린 표지 전용 장치. 어디서 · 언제 · 누가 세 칸에
행사명·날짜·발표자를 넣는다. 정보가 없으면 `div.search` 를 **통째로 지운다**(빈 칸으로 두지 않는다).
표지에서는 오브가 그 장의 Rausch 면이다.

## 3. 도해 카탈로그

무엇을 놓을지는 **말하려는 관계**로 정한다. 예쁜 것으로 정하지 않는다.

| 말하려는 것 | 쓰는 것 | 클래스 | 원본에서 빌린 것 |
|---|---|---|---|
| 순서·인과 | 한 알약 안 3칸 흐름, 결론 칸만 Rausch | `.flow` | 검색바 + 검색 오브 |
| A와 B의 차이 | 2열 카드, 고를 쪽만 2px 잉크 테두리 + 배지 | `.duo` + `.card.pick` + `.band.full` | 포커스된 입력칸 · Guest favorite 배지 |
| 구성요소 셋 | 회색 플레이트에 큰 번호 얹은 카드 3개 | `.trio` + `.card.top` + `.plate` | 사진 먼저인 숙소 카드 |
| 절차 | 잉크 원 번호 목록 | `.steps` | 날짜 선택 칸(선택됨) |
| 두 집합의 관계 | 겹치는 원 두 개 (교집합만 연핑크 `#ffd1da`) | `.venn` | — |
| 수치 대비 | 큰 숫자 두 개 (전은 연회색, 후는 잉크 104px) | `.hero` + `.stat` | 평점 표시 "4.81" |
| 값 나열 | 헤어라인으로 나눈 행 | `.pairs` | 편의시설 목록 |
| 그대로 칠 프롬프트 | 잉크 둥근 블록 + Rausch 라벨 알약 | `.prompt` | — |
| 화면 증거 | 둥글게 자른 사진 + 아래 캡션 | `.shot` / `.frame` | 숙소 사진 |

- **수치 대비의 "후" 숫자는 잉크다.** 원본도 별점과 평점을 노란색이 아니라 잉크로 칠한다. 색이 아니라 크기가 말한다.
- `.plate` 의 번호(`01`)와 배지는 편집된다. 배지는 선택이다 — 필요 없으면 `small.badge` 를 지운다.

**도해는 결론 밴드 한 줄로 닫는다.** 그림만 놓고 넘어가지 않는다.

```html
<div class="band">{결론 문장}<b>{숫자}</b></div>                        <!-- 잉크: 성과·결론 -->
<div class="band" style="display:block;text-align:center">{한 줄}</div>  <!-- 잉크 가운데: 판단 기준 -->
<div class="band rausch">{꼭 기억할 한 줄}</div>                          <!-- Rausch: 덱의 결정적 순간에만 -->
```

밴드는 덱 전체에서 **6개 이하**, 그중 `.band.rausch` 는 **2개 이하**, 프롬프트 블록은 **2개 이하**.

## 4. 쓰기 규칙 (이 스타일 고유)

- 본문 제목에 마침표·물음표를 찍지 않는다(1-④).
- 리드 `.body` 는 **한 문장**. 두 문장을 넘기면 제목이 틀린 것이다.
- 말투는 minimal 보다 한 톤 부드럽게 — 담백하되 딱딱한 명령조는 피한다. 과장·감탄사·마케팅 문구는 여전히 금지.
- 장식용 이모지 금지. `→ ↗ ✓ 01` 같은 기능 기호만.
- 외부 링크는 `이름 ↗` 형태의 밑줄 텍스트 링크로.
- 헤더 좌상단 BRAND 는 **영문 소문자 한 단어**(워드마크처럼 Rausch 로 칠해진다).

## 5. 완료 전 체크

```
□ 배경이 #ffffff 이고, 글자가 #222(순흑 아님)인가
□ Rausch 면이 한 장에 하나 이하인가 (flow strong · band.rausch · skill · ui-btn · orb)
□ .accent 가 제목에만, 한 장에 한 번씩만 걸렸는가
□ 후킹이 표지 한 장에만 있고, 본문 제목은 명사구인가
□ 마무리 장 .close 에 핵심 메시지가 문장 그대로 놓였는가
□ 각진 면(radius 0)이 없는가
□ 그림자가 var(--lift) 한 단뿐이고, 떠 있는 것에만 있는가
□ font-weight 800 이상이 .brand 외에 없는가
□ 배지가 카드 하나에 하나 이하인가 (태그 나열 없음)
□ 표지 검색바에 빈 {자리}가 남지 않았는가 (없으면 통째로 삭제)
□ 각 도해가 결론 밴드로 닫히는가 (밴드 6개 이하, rausch 밴드 2개 이하)
□ 프롬프트 블록이 2개 이하인가
□ 900px·600px 로 줄여도 1단으로 접히는가
```

(공통 요건 체크는 SKILL.md 5절에 있다. 둘 다 돌린다)

검증:

```bash
f="{만든 파일}"
grep -c 'class="slide'                         "$f"          # 장수
grep -o 'class="accent'                        "$f" | wc -l  # 장수와 비슷해야 정상
grep -o 'class="band'                          "$f" | wc -l  # 6 이하
grep -o 'class="band rausch'                   "$f" | wc -l  # 2 이하
grep -nE 'font-weight:(8|9)00|font:(8|9)00'    "$f"          # .brand 한 줄만 나와야 정상
grep -nE 'border-radius:0[;}]'                 "$f"          # 비어야 정상
grep -nE '#000\b|#000000'                      "$f"          # 비어야 정상
grep -oE '[✨🚀🎯💡🔥]'                         "$f"          # 비어야 정상
```

## 6. 이 스타일로 만든 덱을 고칠 때

- **스타일 판별**: `:root` 에 `--rausch` 가 있으면 이 스타일, `--lime` 이 있으면 minimal 이다.
- 뒤에 오는 CSS 선언이 정답이다. 패치를 아래에 쌓지 말고 해당 선언을 찾아 고친다.
- `.slide:nth-of-type(n)` 으로 특정 장을 겨냥하지 않는다. 장 순서가 바뀌면 깨진다.
- Rausch 가 과하다는 말을 들으면 **면부터** 잉크로 바꾼다(`.band.rausch` → `.band`, `.flow strong` 유지). 제목 `.accent` 는 마지막에 건드린다.
- 유틸(kakao-chat 등)은 인용된 제품 화면이라 이 스타일의 둥근 규칙·Rausch 예산에 넣지 않는다.
